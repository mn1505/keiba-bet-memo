# 競馬の購入記録アプリ

競馬で購入予定または購入済みの内容を記録できる、シンプルなローカルWebアプリです。

HTML、CSS、JavaScriptだけで作っているため、フレームワークやビルド作業は不要です。登録した内容はブラウザの `localStorage` に保存されるので、ブラウザを閉じても同じブラウザであればデータが残ります。

## 使い方

1. `index.html` をブラウザで開きます。
2. 日付を入力し、競馬場とレース番号をプルダウンから選びます。
3. 券種を選び、買い方を「通常」「ながし」「ボックス」「フォーメーション」から選びます。
4. 買い方に応じて馬番を選び、1点あたり金額を入力します。買い目文字列、生成点数、合計購入金額は自動で作られます。
5. 必要であればメモとタグを入力します。タグはカンマ区切りで複数入力できます。
6. 「登録する」ボタンを押すと、一覧に購入記録が追加されます。
7. 登録済みの購入記録は「編集」で修正、「複製」で同じ内容を元に新規作成できます。
8. 不要な購入記録は「削除」ボタンで削除できます。
9. 一覧の各購入記録で、結果ステータスを「未確定」「的中」「不的中」から選べます。
10. 的中にした購入記録は、払戻金を入力できます。
11. 一覧の上部に合計購入金額、合計払戻金、収支、回収率が表示されます。
12. 「券種別成績」で、券種ごとの件数、購入金額、払戻金、収支、回収率を確認できます。
13. 「絞り込み」で日付、競馬場、券種、結果ステータス、タグ、買い方を選ぶと、条件に合う購入記録だけを表示できます。
14. キーワード検索では、raceId、買い目、メモ、タグを対象に検索できます。
15. 購入記録一覧の列見出し（日付、競馬場、R、金額、結果、払戻、収支）を押すと並び替えできます。
16. 「リセット」ボタンを押すと、すべての絞り込み条件と検索条件を解除できます。
17. 画面下部の「CSV出力」にある「表示中のデータをCSV出力」ボタンを押すと、購入記録データをCSVファイルとして保存できます。
18. 画面下部の「全データをJSONバックアップ」ボタンを押すと、復元用のJSONファイルを保存できます。
19. 画面上部の「架空資金シミュレーション」で、初期資金、現在残高、合計購入金額、合計払戻金、収支、回収率、残高率を確認できます。
20. 初期資金は変更できます。購入記録を残して初期資金だけ変更する操作と、全購入記録を削除して初期資金を再設定する操作を分けています。
21. JSONバックアップを復元するときは、画面下部でファイルを選び、復元方式を選んでから「JSONバックアップを復元」ボタンを押します。
22. 「分析ダッシュボード」で、表示中の購入記録をもとに基本分析、日付別成績、競馬場別成績、タグ別成績、回収率ランキング、最大払戻・最大損益の記録を確認できます。
23. 「結果データ取り込み」で results.json またはCSVを手動で読み込み、購入記録へ的中結果と払戻金を反映できます。

このアプリは架空資金による記録・シミュレーション用です。実際の馬券購入機能、送金機能、外部投票サイト連携機能はありません。

## v12.5-Aで追加した買い方別入力UI

v12.5-Aでは、券種とは別に「買い方」を選べる入力UIを追加しました。買い方は次の4種類です。

- 通常：従来に近い1点入力です。単勝・複勝は1頭、ワイド・馬連・馬単は2頭、三連複・三連単は3頭を選びます。
- ながし：軸馬と相手馬を選び、複数の買い目を自動生成します。ワイド、馬連、馬単、三連複に対応しています。
- ボックス：選択した複数馬から、券種に応じた全組み合わせを自動生成します。
- フォーメーション：1列目/2列目/3列目、または1着候補/2着候補/3着候補のように列を分けて選びます。

ワイド、馬連、三連複は順不同として昇順に整え、同じ買い目の重複を除外します。馬単、三連単は順序ありとして保存します。三連単のながしは今回未実装のため、三連単ではフォーメーションを使ってください。

登録前には「生成プレビュー」で、生成点数、買い目一覧、合計購入金額を確認できます。金額欄は「1点あたり金額」として扱い、合計購入金額は `生成点数 × 1点あたり金額` で計算します。生成点数が50点を超える場合は警告し、100点を超える場合は登録前に確認ダイアログを表示します。

新規登録時は、生成された各買い目を個別の購入記録として保存します。同時に生成された買い目には同じ `generatedGroupId` を付け、各記録には `purchaseMode` を保存します。既存データや古いJSONバックアップにこれらの項目がなくても、読み込み時に `purchaseMode` は「通常」、`generatedGroupId` は空文字として扱います。

CSV出力には `purchaseMode` と `generatedGroupId` を追加しました。JSONバックアップ/復元にも同じ項目を含めます。分析ダッシュボードには、買い方別成績として件数、購入金額、払戻金、収支、回収率、的中率を表示します。

## v2で追加した結果・収支管理

v2では、登録済みの購入記録ごとに結果ステータスと払戻金を記録できます。

- 結果ステータスは「未確定」「的中」「不的中」から選びます。
- 「的中」を選ぶと払戻金を入力できます。
- 「未確定」または「不的中」に戻すと、払戻金は0円になります。
- 収支は「合計払戻金 - 合計購入金額」で計算します。
- 回収率は「合計払戻金 ÷ 合計購入金額 × 100」で計算します。
- 購入金額が0円の場合、回収率は0.0%として表示します。

結果ステータスや払戻金を変更すると、登録内容と同じくブラウザの `localStorage` に保存されます。以前のバージョンで保存したデータは、結果ステータスがない場合は「未確定」、払戻金がない場合は0円として読み込みます。

## v3で追加した券種別成績

v3では、全体集計に加えて「券種別成績」を表示します。対象の券種は「単勝」「複勝」「ワイド」「馬連」「馬単」「三連複」「三連単」です。

券種ごとに、次の項目を確認できます。

- 件数
- 合計購入金額
- 合計払戻金
- 収支
- 回収率

計算式は全体集計と同じです。

- 収支：合計払戻金 - 合計購入金額
- 回収率：合計払戻金 ÷ 合計購入金額 × 100

未確定の購入記録も購入金額に含めます。払戻金が未入力の購入記録は0円として扱います。購入金額が0円の券種は、回収率を0.0%として表示します。

券種別成績は画面上で計算して表示するだけなので、`localStorage` の保存形式はv2から変えていません。既存データはそのまま使えます。

## v4で追加した絞り込み機能

v4では、登録した購入記録一覧を条件で絞り込めます。

- 日付：日付入力で指定します。空欄の場合はすべての日付を表示します。
- 競馬場：登録済みデータから自動で選択肢を作ります。「すべて」を選ぶと競馬場では絞り込みません。
- 券種：「すべて」「単勝」「複勝」「ワイド」「馬連」「馬単」「三連複」「三連単」から選びます。
- 結果：「すべて」「未確定」「的中」「不的中」から選びます。

絞り込み中は、一覧の件数が「表示中：3件 / 全12件」のように表示されます。

全体集計と券種別成績も、現在表示している購入記録だけを対象に再計算します。たとえば東京競馬場だけに絞り込むと、合計購入金額、合計払戻金、収支、回収率、券種別成績は東京の購入記録だけで計算されます。

絞り込み条件は画面表示用の条件なので、`localStorage` の保存形式は変えていません。v1からv3までの既存データはそのまま使えます。

## v5で追加したCSV出力機能

v5では、登録済みの購入記録データをCSVファイルとしてダウンロードできます。

- 一覧上部の「表示中のデータをCSV出力」ボタンを押すとCSVを保存できます。
- 絞り込み中は、現在表示されている購入記録だけをCSV出力します。
- 絞り込み条件がない場合は、登録済みの全データをCSV出力します。
- 出力対象が0件の場合は、CSVを作らず、画面にメッセージを表示します。

CSVには次の項目が入ります。

- `date`
- `raceId`
- `track`
- `race`
- `betType`
- `combination`
- `purchaseMode`
- `generatedGroupId`
- `amount`
- `status`
- `payout`
- `profit`
- `memo`
- `tags`
- `createdAt`
- `updatedAt`

`profit` は購入記録ごとに `payout - amount` で計算します。CSVはUTF-8 BOM付きで出力するため、日本語を含む内容でもExcelで文字化けしにくくなっています。カンマ、改行、ダブルクォートを含むメモも壊れにくいようにCSV用のエスケープ処理を入れています。

ファイル名は `keiba-bet-memo-YYYY-MM-DD.csv` の形式です。Excel、Googleスプレッドシート、Numbersなどの表計算ソフトで開けます。

## v6で追加したバックアップ/復元機能

v6では、登録済みの全データをJSONファイルとしてバックアップし、あとから復元できます。

### バックアップ方法

1. 画面下部の「バックアップ/復元」にある「全データをJSONバックアップ」ボタンを押します。
2. `keiba-bet-memo-backup-YYYY-MM-DD.json` という名前のJSONファイルが保存されます。

JSONには次の情報が入ります。

- `appName`
- `version`
- `exportedAt`
- `data`

`data` の中に、購入記録データ、raceId、結果ステータス、払戻金、メモ、タグ、登録日時、更新日時、初期資金などのシミュレーション設定、結果データ取り込み履歴が入ります。画面で絞り込み中でも、JSONバックアップは全データを保存します。

### 復元方法

1. 「復元ファイル」でJSONバックアップファイルを選びます。
2. 「復元方式」を選びます。
   - 「現在のデータを置き換える」：今のデータを消して、バックアップ内容に入れ替えます。
   - 「現在のデータに追加する」：今のデータを残したまま、バックアップ内容を追加します。
3. 「JSONバックアップを復元」ボタンを押します。
4. 確認メッセージが出るので、内容を確認して実行します。

復元後は `localStorage` に保存し直し、一覧、全体集計、券種別成績、絞り込み表示、シミュレーション集計を再計算します。追加復元では、同じ `id` が重複しにくいように必要に応じて新しい `id` を付け直します。古いJSONバックアップに初期資金がない場合は、デフォルトの100,000円として扱います。JSONではないファイルや形式が違うファイルを選んだ場合は、画面にエラーを表示します。

### CSV出力との違い

CSV出力は、Excelやスプレッドシートで購入記録を分析するための機能です。絞り込み中は表示中のデータだけを出力します。CSVには `tags`、`createdAt`、`updatedAt` も含まれます。初期資金や現在残高などの設定は、個別の購入記録ではないためCSV行には入れず、JSONバックアップに保存します。

JSONバックアップは、アプリに復元するための機能です。絞り込み条件に関係なく、現在保存されている全データとシミュレーション設定を出力します。スマホ買い替えやブラウザデータ削除に備える場合は、CSVではなくJSONバックアップを保存してください。

### スマホ買い替え時の使い方

1. 古いスマホで「全データをJSONバックアップ」を押して、JSONファイルを保存します。
2. 保存したJSONファイルをGoogle Drive、メール、USB接続などで新しいスマホに移します。
3. 新しいスマホでアプリを開きます。
4. 「復元ファイル」でJSONファイルを選びます。
5. 通常は「現在のデータを置き換える」を選び、「JSONバックアップを復元」を押します。
6. すでに新しいスマホでも購入記録を登録している場合は、「現在のデータに追加する」を選ぶと、既存データを残したまま追加できます。

## 入力UIとデザインの既存仕様

購入記録フォームの競馬場は、中央競馬の競馬場から選ぶプルダウンです。レース番号も「1R」から「12R」までのプルダウンで選びます。

レース番号プルダウンには競馬場名を含めません。「東京11R」のような競馬場名とレース番号が結合した選択肢は使わず、選択肢は `1R` から `12R` のみです。

既存データの `place` と `race` はこれまで通り文字列として読み込むため、以前に自由入力した競馬場や「東京11R」のようなレース名が残っていても、一覧表示、絞り込み、CSV出力、JSONバックアップ/復元はそのまま使えます。編集時は保存前に `1R` から `12R` の形式へ正規化します。

画面の配色は、白、薄いグレー、薄い青、濃いネイビーを中心にした管理画面寄りの見た目へ調整しました。

## v7で変更した購入記録入力

画面上の見出しを「購入記録」に変更しました。登録フォームの「買い目」は自由入力欄ではなく、券種に応じて必要な馬番入力欄が表示される形式に変更しています。

- 単勝、複勝：馬番を1つ入力します。
- ワイド、馬連：馬番を2つ入力します。
- 馬単：1着、2着の順に馬番を入力します。
- 三連複：馬番を3つ入力します。
- 三連単：1着、2着、3着の順に馬番を入力します。

馬番欄は `1` から `18` を選びやすい入力欄です。登録時には券種と馬番から `combination` に入る買い目文字列を自動生成します。

- 単勝、複勝：`7`
- ワイド、馬連：`7-13`
- 馬単：`7→13`
- 三連複：`7-13-15`
- 三連単：`7→13→15`

ワイド、馬連、三連複は順不同のため、馬番を昇順に並べて保存します。馬単、三連単は順序が重要なので、入力した順番のまま保存します。

必要な馬番が空欄の場合、馬番が1〜18以外の場合、同じ購入記録内で馬番が重複している場合は登録できません。以前のバージョンで保存した `betNumbers` の文字列はそのまま読み込むため、既存データの一覧表示、集計、絞り込み、CSV出力、JSONバックアップ/復元は引き続き使えます。

バックアップ/復元エリアは、登録フォーム、一覧、集計、絞り込み、CSV出力より下の画面下部に移動しました。

## v7で追加した編集・複製・タグ管理

v7では、登録済みの購入記録をあとから直しやすくするため、編集、複製、タグ管理を追加しました。

- 一覧の「編集」ボタンを押すと、登録フォームに内容が入り、日付、競馬場、レース番号、券種、馬番、購入金額、結果、払戻金、メモ、タグを修正できます。
- 編集中は「編集をキャンセル」ボタンで通常の登録状態に戻せます。
- 編集を保存すると `updatedAt` だけを現在日時に更新し、一覧、全体集計、券種別成績、絞り込み表示を再描画します。
- 一覧の「複製」ボタンを押すと、元の購入記録をコピーして新しい購入記録を作ります。複製したデータは新しい `id` になり、結果ステータスは「未確定」、払戻金は0円に戻ります。
- タグ欄はカンマ区切りで複数入力できます。内部では `tags` 配列として保存し、一覧では控えめなラベルとして表示します。
- 新規登録時は `createdAt` と `updatedAt` を現在日時で保存します。編集時は `updatedAt` のみ更新します。
- 購入金額が100円未満、または100円単位ではない場合は、登録前に確認メッセージを表示します。確認すればそのまま保存できます。

CSV出力には `raceId`、`tags`、`createdAt`、`updatedAt` 列も含まれます。JSONバックアップ/復元にもraceId、タグ、登録日時、更新日時が含まれます。

以前のデータに `tags`、`createdAt`、`updatedAt` がない場合でも、表示、編集、集計、CSV出力、JSONバックアップ/復元で壊れないようにしています。古い `combination` / `betNumbers` の文字列も維持します。

## v8で追加した架空資金シミュレーション機能

v8では、実際のお金ではなく架空資金で購入記録を管理するシミュレーション機能を追加しました。画面上にも「これは架空資金によるシミュレーションです。実際の馬券購入機能はありません。」と表示しています。

- 初期資金のデフォルトは100,000円です。
- 初期資金はユーザーが変更でき、`localStorage` に保存されます。
- 現在残高は、保存済みの全購入記録から毎回再計算します。
- 計算式は `現在残高 = 初期資金 - 合計購入金額 + 合計払戻金` です。
- 払戻金を手入力・編集した場合も、全データから再計算するため二重加算は起きません。
- 新規登録時と編集時に、購入金額が現在残高を超える場合は保存できません。
- 編集時は、編集対象自身の購入金額を一度除外して残高不足を判定します。
- シミュレーション集計では、初期資金、現在残高、合計購入金額、合計払戻金、収支、回収率、残高率を確認できます。
- 残高率は `現在残高 ÷ 初期資金 × 100` で計算します。初期資金が0円の場合は0.0%として表示します。
- 初期資金だけ変更する操作と、全購入記録を削除して初期資金も再設定する操作を選べます。どちらも実行前に確認メッセージを表示します。
- 絞り込み中でも、現在残高は全購入記録を基準に計算します。
- JSONバックアップには購入記録だけでなく、初期資金などのシミュレーション設定も含まれます。

このアプリには、実際の馬券購入、送金、外部投票サイト連携の機能はありません。購入記録と架空資金の残高をローカルブラウザ内で管理するだけのアプリです。

## v9で追加した分析ダッシュボード

v9では、保存済みの購入記録を画面上で再計算して表示する「分析ダッシュボード」を追加しました。

- 分析は、現在の絞り込み条件を反映します。日付、競馬場、券種、結果ステータスで絞り込むと、分析ダッシュボードも同じ表示中データだけを対象に再計算します。
- 現在残高はこれまで通り、上部の架空資金シミュレーションで全記録を基準に計算します。
- 基本分析では、表示中の購入記録件数、的中件数、不的中件数、未確定件数、的中率、合計購入金額、合計払戻金、収支、回収率、平均購入金額、平均払戻金、最大払戻金、最大プラス収支、最大マイナス収支を確認できます。
- 的中率は `的中件数 ÷ 確定済み件数 × 100` で計算します。確定済み件数は `的中件数 + 不的中件数` です。未確定の購入記録は的中率の分母に含めません。確定済み件数が0件の場合は0.0%として表示します。
- 日付別成績、競馬場別成績、タグ別成績では、件数、購入金額、払戻金、収支、回収率、的中率を表で確認できます。
- タグがない購入記録は「タグなし」として集計します。1件の購入記録に複数タグがある場合は、それぞれのタグに重複して集計するため、タグ別集計の購入金額合計は全体合計と一致しないことがあります。
- 回収率ランキングでは、購入金額が0円の項目を除外し、件数も一緒に表示します。1件だけの項目には「サンプル少」と表示します。
- 最大払戻、最大プラス収支、最大マイナス収支の購入記録では、日付、競馬場、レース番号、券種、買い目、購入金額、払戻金、収支、タグを確認できます。
- 分析結果そのものは `localStorage` やJSONバックアップには保存しません。購入記録から毎回再計算するため、JSONバックアップ復元後も保存済みデータをもとに再描画されます。

## v10で追加した結果データ取り込みの土台

v10では、Webスクレイピングや外部サイト自動取得は実装せず、手元の結果データファイルを読み込んで購入記録と照合する土台を追加しました。

### raceId

各購入記録には `raceId` を保存します。形式は `YYYYMMDD-TRACK-レース番号` です。

- 例：`20260502-TOKYO-11R`
- 例：`20260503-KYOTO-10R`

`TRACK` は中央競馬10場を英字コードにしたものです。

- 札幌：`SAPPORO`
- 函館：`HAKODATE`
- 福島：`FUKUSHIMA`
- 新潟：`NIIGATA`
- 東京：`TOKYO`
- 中山：`NAKAYAMA`
- 中京：`CHUKYO`
- 京都：`KYOTO`
- 阪神：`HANSHIN`
- 小倉：`KOKURA`

古い保存データや古いJSONバックアップに `raceId` がない場合は、読み込み時や復元時に日付、競馬場、レース番号から自動生成します。古いデータに `東京11R` のようなレース文字列が残っている場合も、可能な範囲で `11R` として扱います。

### results.json形式

「結果データ取り込み」で選ぶJSONは、次のような配列形式です。

```json
[
  {
    "raceId": "20260502-TOKYO-11R",
    "betType": "ワイド",
    "combination": "7-13",
    "payout": 680
  },
  {
    "raceId": "20260502-TOKYO-11R",
    "betType": "馬単",
    "combination": "7→13",
    "payout": 2540
  }
]
```

`payout` は100円あたりの払戻金として扱います。購入金額が500円で `payout` が680円の場合、購入記録へ反映される払戻金は `680 × (500 ÷ 100) = 3,400円` です。

### CSV形式

CSVも読み込めます。ヘッダー付きで、次の列名を使います。

```csv
raceId,betType,combination,payout
20260502-TOKYO-11R,ワイド,7-13,680
20260502-TOKYO-11R,馬単,7→13,2540
```

日本語を含むCSVを扱えるようにし、最低限のカンマ区切りとダブルクォートに対応しています。

### 照合と反映

取り込んだ結果データは、すぐには反映されません。まずプレビューで次の内容を確認します。

- 読み込んだ結果データ件数
- 照合できた購入記録件数
- 的中予定件数
- 不一致件数
- 対象raceId一覧
- 的中予定の購入記録一覧

照合は `raceId`、`betType`、`combination` で行います。ワイド、馬連、三連複は順不同として扱い、`13-7` と `7-13` は同じ買い目として照合します。馬単、三連単は順序ありとして扱います。半角ハイフン、全角ハイフン、矢印、`>`、カンマ、空白などの区切り文字のゆらぎにもある程度対応します。

プレビュー後に「結果を反映」を押すと、一致した購入記録を「的中」にし、購入金額に応じて計算した払戻金を保存します。反映後は一覧、集計、分析ダッシュボード、現在残高が再計算されます。

### 不的中一括反映

「対象レースの未確定を不的中にする」を押すと、取り込んだ結果データに含まれる `raceId` と同じレースだけを対象に、結果データと一致しなかった未確定の購入記録を「不的中」にできます。実行前に確認メッセージが出ます。すでに「的中」または「不的中」になっている購入記録は上書きしません。

### 取り込み履歴

結果データ取り込み履歴は `localStorage` に保存します。履歴には取り込み日時、ファイル名、結果データ件数、照合件数、反映件数、対象raceIdを保存し、画面上には直近数件を表示します。JSONバックアップ/復元にも取り込み履歴を含めます。

この機能は結果データを手動で読み込むための土台です。JRAなど外部サイトのWebスクレイピング、外部サイト自動取得、実際の馬券購入、送金、外部投票サイト連携は実装していません。

## v11で追加したresults.json作成ツール

v11では、Macのターミナル上で手入力し、アプリが読み込める `results.json` を作成するPythonツールを追加しました。


このツールは、JRAや地方競馬などのレース結果・払戻情報をユーザーが自分で確認し、手入力で `results.json` にするための個人利用向け補助ツールです。Webスクレイピング、外部サイト自動取得、外部API連携は行いません。

ターミナルでは次の項目を順番に入力します。

- 競馬場：中央競馬10場から番号または日本語名で選びます。`raceId` では `TOKYO`、`KYOTO` などの英字コードに変換されます。

作成されるJSONは次の形式です。

```json
[

    "payout": 680
  }
]
```

`payout` は100円あたりの払戻金として扱います。購入金額が500円で `payout` が680円の場合、アプリに反映される払戻金は3,400円です。

サンプルとして `results.sample.json` も追加しています。JSON形式を確認したい場合や、アプリの取り込みテストをしたい場合に使えます。

## v12.5-Bで追加した保存HTML取込〜的中照合の自動化強化

v12.5-Bでは、ブラウザで保存したローカルHTMLファイルを読み込み、払戻情報候補を抽出して、アプリが読み込める `results.json` を作成しやすくしました。v12.7以降は外部サイトへPythonやブラウザJSから直接アクセスせず、保存済みHTMLを個人利用の範囲でローカル処理するための補助ツールです。

```text
[2] 馬連 7-13 1240円 table 1 row 5
```

候補は、すべて採用、一部番号だけ採用、すべて除外を選べます。候補が0件の場合や表記が合わない場合は、v11の `tools/create_results_json.py` と同じ感覚で、券種、馬番、100円あたりの払戻金を手動追加できます。採用前には最終的に出力される結果データを確認できます。

7. 出力された `results.json` をBAKENONIの「結果データ取り込み」で読み込み、プレビュー確認後に結果を反映します。

v12.7以降、このツールは保存済みHTMLのローカル読み込みだけを行います。外部サイトへの直接アクセス、URL取得、連続リトライ、自動巡回、User-Agent 偽装、ログイン回避、CAPTCHA回避、有料ページ回避などは実装していません。

作成されるJSONはv10/v11と同じ形式です。

```json
[
  {
    "raceId": "20260502-TOKYO-11R",
    "betType": "ワイド",
    "combination": "7-13",
    "payout": 680
  }

```

`payout` は100円あたりの払戻金です。作成後は、アプリの「結果データ取り込み」で `results.json` を選び、「プレビューを作成」で照合内容を確認してから「結果を反映」を押します。

この機能は、ログインが必要なページ、有料情報、CAPTCHA、アクセス制限回避には使わないでください。外部サイトの利用規約や権利を尊重し、取得データは個人利用に留めてください。あとから `scraped_pages/` 内のHTMLを見て、対象サイトに合わせた抽出ロジックを検討できます。将来拡張用の設定例として `tools/scraper_config.sample.json` も追加しています。必要なPythonライブラリは `requirements.txt` にまとめています。

## v12.7で追加した1日分・競馬場別の払戻一覧HTML取込

v12.7では、1レースごとの結果ページではなく、1R〜12Rの払戻が一覧掲載されているページをChromeなどで保存し、そのローカルHTMLから1日分・競馬場別の結果JSONを作れるようにしました。netkeibaのJRA「結果・払戻一覧」ページを保存したHTMLも想定しています。外部サイトへPythonやブラウザJSから直接アクセスせず、保存済みHTMLのローカル解析だけを行います。

推奨ファイル名は次の形式です。ファイル名から日付と競馬場を優先して推定します。

```text
20260502-TOKYO-all.html
20260502-TOKYO-payouts.html
```

ChromeでHTMLを保存する例:

2. 日付と競馬場を選び、1R〜12Rの払戻一覧が表示されていることを確認します。
3. BAKENONI HTML保存拡張、または `Command + S` でHTMLを保存します。
4. 可能なら形式を「ウェブページ、HTMLのみ」にして保存します。
5. 推奨ファイル名の例として `20260502-TOKYO-all.html` にします。

ターミナルで次を実行します。

```bash
python3 tools/scrape_results_trial.py
```

メニューで「1日分の払戻一覧HTMLから結果JSONを作成」を選び、保存済みHTMLのパスを入力します。例:

```text
/Users/nagahisamichiya/Downloads/20260502-TOKYO-all.html
```

ツールはファイル名、HTMLコメント、HTML本文から日付と競馬場を推定します。推定結果は画面に表示され、必要なら手入力で修正できます。日付は `2026-05-02`、`20260502`、`2026年5月2日` などに対応しています。競馬場は札幌、函館、福島、新潟、東京、中山、中京、京都、阪神、小倉と、それぞれの英字コードに対応しています。

netkeiba保存HTMLでは、HTML内に `payback_list.html?kaisai_date=YYYYMMDD` が残っている場合、その日付も推定に使います。ファイル名が `20260502-TOKYO-all.html` のような形式なら、日付は `2026-05-02`、競馬場は `東京`、コードは `TOKYO` として優先的に推定します。

HTML内では `1R`、`１Ｒ`、`第1レース`、`第１レース`、`1 レース` などの表記からレースブロックを検出します。対象券種は単勝、複勝、ワイド、馬連、馬単、三連複、三連単です。円表記やカンマ区切りの払戻金を100円あたりの払戻金として扱い、ワイド・馬連・三連複は昇順の `7-13` 形式、馬単・三連単は順序ありの `7→13` 形式へ正規化します。

netkeibaの払戻一覧HTMLでは、保存HTML上の見出しやテーブル周辺からレース番号を取れない場合があります。その場合でも、`betType`、`combination`、`payout` が取れている候補は捨てずに保持し、払戻セットの並び順から `1R`〜`12R` を推定します。基本的には新しい「単勝」が出た位置を次レースの開始候補として扱い、最初の単勝から次の単勝直前までを `1R`、次を `2R` という順に割り当てます。


JSON形式は既存の結果データ取り込みと同じ配列形式です。

```json

  {
    "raceId": "20260502-TOKYO-11R",
    "betType": "ワイド",
    "combination": "7-13",
    "payout": 680
  }
```

1. BAKENONIを開く
2. 結果データ取り込みで `results/20260502-TOKYO-all-results.json` を選択
3. プレビューを確認
4. 結果を反映
5. 対象レースの未確定を不的中にする

BAKENONI本体の結果データ取り込みは、JSON配列内に複数の `raceId` が含まれていても対象raceId一覧を作り、購入記録と `raceId` / `betType` / `combination` で照合します。1R〜12R分の結果JSONを読み込んでも、購入記録があるraceIdだけが的中反映の対象になります。「対象レースの未確定を不的中にする」も、取り込んだ結果データに含まれるraceIdだけを対象にします。

このv12.7機能は保存済みHTMLのローカル解析用です。外部サイトへのURL巡回、自動スクレイピング、自動リトライ、アクセス制限回避、ログイン回避、CAPTCHA回避、有料情報取得、User-Agent偽装は実装していません。実際の馬券購入、送金、外部投票サイト連携もありません。外部サイトの利用規約や権利を尊重し、個人利用の範囲に留めてください。

## Android Chromeでホーム画面に追加する方法

Android ChromeでPWAとして追加するには、HTTPSのURLで開く必要があります。`index.html` を直接開く方法では、通常のWebページとしては使えますが、ホーム画面追加やオフライン用の仕組みが正しく動かない場合があります。

GitHub Pages、Netlify、Vercelなどにこのフォルダの中身を公開すると、HTTPSで開けるためAndroid Chromeから追加しやすくなります。

HTTPSで公開したページをAndroid Chromeで開いたら、Chrome右上のメニューから「ホーム画面に追加」を選びます。追加名は「購入記録」と表示されます。

登録した購入記録はこれまで通りブラウザの `localStorage` に保存されます。ホーム画面から開いた場合も、同じChrome内のデータとして保存されます。

パソコンで表示を確認するだけなら、このフォルダで簡易サーバーを起動できます。`http://localhost` は開発用として扱われるため、同じパソコンのChromeではPWAの動作確認にも使えます。

```bash
python3 -m http.server 8000
```

同じパソコンで確認する場合は、Chromeで次のURLを開きます。

```text
http://localhost:8000
```

Androidスマホで同じWi-Fi内のパソコンにアクセスする場合、次のようなURLでも画面表示は確認できます。ただしHTTP接続のため、PWAのインストール確認にはHTTPS公開したURLを使ってください。

```text
http://パソコンのIPアドレス:8000
```

## ローカルでの開き方

このアプリはサーバーを起動しなくても使えます。

1. このフォルダを開きます。
2. `index.html` をダブルクリックします。
3. ブラウザでアプリが表示されます。

データは開いたブラウザの `localStorage` に保存されます。別のブラウザや別の端末では同じデータは表示されません。
